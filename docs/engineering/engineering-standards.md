# Engineering standards

These rules apply to `relgap` (they're shared with the sibling tool [tfcensus](https://github.com/sassdavid/tfcensus)).
[CLAUDE.md](../../CLAUDE.md) summarizes the ones that matter most day to day.
Stack choices and versions: [stack.md](stack.md). The reasoning behind them is in [adr/](adr/).

## Repository layout

```
cmd/<tool>/main.go        # only: os.Exit(cli.Run(ctx, os.Args, os.Stdout, os.Stderr))
internal/cli/             # cobra commands, flag binding, no business logic
internal/<domain>/        # one package per concept (e.g. version, registry, scan, source)
internal/render/          # tty / plain / md / json / sarif renderers
internal/httpx/           # retrying, caching, rate-limited HTTP client
internal/testutil/        # fixtures, fakes, golden helpers
testdata/                 # golden files, recorded HTTP/AWS responses, fixture repos
docs/                     # user docs; docs/cli/ is generated by cobra/doc and checked in
schemas/                  # JSON Schemas for config and report output (versioned)
```

- Everything is under `internal/` until an external consumer asks for an API. A public `pkg/` is a promise we don't make yet.
- No package-level mutable state. Commands get an `*app.Deps` struct with clients, config, logger, clock and fs. This makes every command testable without globals.
- Interfaces are defined in the package that *uses* them. Keep them small (1–3 methods), at the boundary of AWS, GitHub, the filesystem and exec.

## Process & control flow

- `main` creates `ctx` with `signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)`. Every I/O call takes `ctx`.
- Fan-out uses `errgroup.WithContext` + `SetLimit(n)`, with nested limits where fan-out nests (e.g. tools → API pages). Limits are configurable (`--concurrency`) and have sane defaults.
- A failure in one target (one repo, one tool) does not abort the run. It becomes a per-target error in the report, and the exit code reflects it. `--fail-fast` opts in to aborting.
- External processes (`mise`, `git`) go through one `execx` package. It handles ctx cancellation, captured stderr, a timeout, the env allowlist and a logged command line with secrets redacted.

## Errors & exit codes

- Wrap with `fmt.Errorf("verb object: %w", err)`, aggregate with `errors.Join`, classify with sentinel or typed errors (`ErrAuth`, `ErrNotFound`, `ErrRateLimited`).
- User-facing messages say **what failed, why, and what to do** ("GitHub rate limit reached (60/h unauthenticated). Set GITHUB_TOKEN or run `gh auth login`.").

| Code | Meaning |
|---|---|
| 0 | success, nothing matched `--fail-on` |
| 1 | runtime error (partial results may still be printed) |
| 2 | usage / config error |
| 3 | success, but findings matched `--fail-on` (CI gate) |
| 4 | authentication / authorization error |
| 130 | interrupted |

Terraform's `-detailed-exitcode` convention (2 = changes) is deliberately *not* reused, because 2 is the
cobra/POSIX usage-error code. Docs explain the mapping.

## Output contract

- **stdout = data, stderr = logs and progress.** Piping must never capture spinners or log lines.
- `--format tty|plain|md|json|sarif` (not every command supports sarif). Default: `tty` when stdout is a TTY, otherwise `plain`.
- JSON output is an envelope: `{"schema_version": "1", "tool": "...", "version": "...", "generated_at": "...", "data": {...}, "errors": [...]}`. A JSON Schema lives in `schemas/` and is tested. Breaking a schema bumps `schema_version`.
- Colors follow `NO_COLOR`, `CLICOLOR_FORCE`, `--color auto|always|never` and TTY detection.
- Nothing ever prints secrets. Tokens are redacted in logs and debug HTTP dumps.

## Configuration

Precedence: **flags > env (`RELGAP_*`) > project file > user file > defaults**.
- User file: `$XDG_CONFIG_HOME/<tool>/config.yaml` (adrg/xdg; XDG layout on macOS too).
- Project file: `.<tool>.yaml` found by walking up to the git root.
- Cache: `$XDG_CACHE_HOME/<tool>/`.
- `<tool> config show --sources` prints the effective value of every key and where it came from.
- `<tool> config validate` checks the file against the JSON Schema in `schemas/`.
- Unknown keys are an error, not silently ignored. A known pain with Claude Code settings motivated this rule.

## Logging

- Structured logging via `log/slog` (see [ADR-0004](adr/0004-logging.md)).
- `-v` = info, `-vv` = debug, `-vvv` = trace with HTTP dumps (redacted). `-q` = errors only.
- `--log-format text|json`, `--log-file path`.
- Log lines carry attributes (`repo`, `tool`, `version`), not prose with values baked in.

## Interactivity

- Commands are non-interactive by default and work in CI with no TTY.
- Prompts only appear when stdin and stdout are TTYs and `--no-input` / `CI=true` is not set. See [ADR-0007](adr/0007-interactive-prompts.md).
- relgap has no destructive or state-changing actions. If one is ever added, it requires either an interactive confirmation or an explicit `--yes`.

## Code quality

- `golangci-lint` with the config from [ADR-0008](adr/0008-lint-config.md); `gofumpt` + `goimports`.
- `go test -race ./...` must pass on Linux and macOS; Windows also runs in CI.
- Every bug fix adds a regression test. Every new parser or adapter adds fixtures and golden files.
- Exported identifiers need doc comments; package docs live in `doc.go`.
- Commits follow Conventional Commits, which drives release notes ([ci-and-release.md](ci-and-release.md)).

## Security & supply chain

- Dependencies are minimal and justified in `stack.md`. Renovate keeps them current, with a minimum release age of 3 days.
- `govulncheck` runs in CI. GitHub Actions are pinned by SHA. `zizmor` audits workflows.
- Releases are signed (cosign keyless), ship an SBOM (syft) and GitHub build-provenance attestations.
- Every release archive carries the license notices of the code compiled into it, and CI rejects forbidden, restricted or unknown dependency licenses ([ADR-0012](adr/0012-third-party-notices.md)).
- No telemetry, ever. Network calls go only to the documented endpoints for each tool.
- Read-only by default. Any write to cloud or state is opt-in, explicit and logged.
