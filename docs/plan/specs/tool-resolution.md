# Spec: tool resolution and the override registry

Maps a name ("terraform", "tf", "TERRAFORM_VERSION", "hashicorp/aws", "argo-cd") to a `ToolSpec`:
repo, version scheme, ordered changelog sources, EOL product and OSV packages.

## Resolution order (first hit wins, fields merge downward)
1. **Explicit syntax:** `github:owner/repo`, `aqua:owner/repo`, `tfprovider:ns/name` (→ registry.terraform.io → source repo), `chart:repo/name` (→ Artifact Hub → source repo), `npm:`/`pypi:` (→ package metadata repo URL).
2. **User config** `tools.<name>` overrides ([config.md](config.md)).
3. **relgap override registry:** `registry/<tool>.yaml`, embedded in the binary and refreshable from the repo (`relgap registry update`, ETag-cached).
4. **mise registry:** `mise registry --json` if mise is installed (1,074 entries). Otherwise an embedded snapshot of `registry/*.toml` (MIT, attributed). The first `aqua:`, `github:` or `ubi:` backend gives `owner/repo`; `aliases` give names.
5. **aqua registry:** an embedded index of the aqua registry's merged `registry.yaml` supplies `repo_owner/repo_name`, `version_prefix`, `version_filter`, `version_source`.
6. **endoflife.date identifiers:** `pkg:github/owner/repo` → EOL product.
7. **Heuristic:** search GitHub for an exact repo-name match, but only with `--guess`, and always reported as low-confidence.

The snapshots are regenerated by a `mise run registry:snapshot` task and committed. The `registry.yml`
workflow runs `mise run registry:age` weekly and on snapshot changes, and fails when a snapshot's
`commit_date` is over 30 days old.

Both snapshots are embedded, not fetched on first use (open question Q8, recorded here at M11).
The aqua index keeps only what resolution reads: name, repo, aliases and the three version
fields. On 2026-11-09 it had 2,351 entries in 154 KB (`internal/registry/snapshot/aqua.json`),
next to the mise snapshot's 1,023 entries in 86 KB. Each keeps its MIT license beside it as
`<name>.LICENSE`.

## Override registry entry (`registry/<tool>.yaml`)

```yaml
# registry/kubectl.yaml
name: kubectl
aliases: [kubernetes, k8s, KUBECTL_VERSION]
repo: kubernetes/kubernetes
version:
  tag_prefix: "v"
  exclude: "-(alpha|beta|rc)\\."     # regex on the tag
  universe: tags                     # tags | releases (what defines "versions in range")
sources:                             # tried and merged in order
  - kind: changelog-file
    path_template: "CHANGELOG/CHANGELOG-{major}.{minor}.md"
    ref: master
    heading: "^v{version}$"           # H1 per version
    ignore_sections: ["Dependencies"] # k8s "Dependencies › Removed" ≠ feature removals
  - kind: upgrade-notes
    from_heading: "Urgent Upgrade Notes"
eol: { product: kubernetes, cycle: "{major}.{minor}" }
osv:
  - { ecosystem: Go, name: k8s.io/kubernetes }
breaking_markers: ["ACTION REQUIRED"]
```

Schema: `schemas/registry-v1.json`. `relgap registry lint` validates an entry, and `relgap registry test kubectl 1.36.0..1.37.2` runs it live and prints which sources produced what.

## Package registry lookups (`tfprovider:`, `chart:`, `npm:`, `pypi:`)

The registries answer first, so a curated tool resolves offline and gets its entry:

- `tfprovider:<namespace>/<name>` matches the tool whose repo is `<namespace>/terraform-provider-<name>`.
- `npm:<package>` and `pypi:<package>` match a curated entry that lists the package in `osv`
  (`npm:@anthropic-ai/claude-code` is claude-code), then a mise entry with an `npm:` or `pipx:`
  backend that also names a repository.

Otherwise `internal/registry/remote` asks the package registry through `httpx`, and the `repo`
field's layer names the service:

| Prefix | Request | Repository from |
|---|---|---|
| `tfprovider:` | `registry.terraform.io/v1/providers/<ns>/<name>` | `source` |
| `chart:<repo>/<name>` | `artifacthub.io/api/v1/packages/helm/<repo>/<name>` | the chart's own source (below) |
| `chart:<url>/<name>` | `artifacthub.io/api/v1/repositories/search?url=<url>`, then the package | as `chart:<repo>/<name>` |
| `npm:` | `registry.npmjs.org/<package>/latest` | `repository`, then `homepage`, then `bugs` |
| `pypi:` | `pypi.org/pypi/<package>/json` | `project_urls` Source, Source Code, Repository, Code, GitHub, Homepage, then any GitHub URL, then `home_page` |

A package registry only names the repository. relgap reads no changelog URL from it, such as PyPI's
`project_urls.Changelog`; the changelog sources come from the tool's entry or the repository.

A repository that a registry knows takes that tool's entry, as `github:` does. A chart never does:
its repository can be the application's own, whose entry describes app versions, and a chart pin
carries a chart version. Artifact Hub often lists both. relgap picks the link into a
subdirectory (`argoproj/argo-helm/tree/main/charts/argo-cd`), or a GitHub Pages repository URL.
Otherwise it picks the link whose repository is named like the chart.

The tag prefix comes from the repository's tags, listed once per lookup. Each tag that ends in a
chart version Artifact Hub lists makes the rest of the tag a candidate prefix. The candidate that
covers the most versions wins; on a tie, the one that holds the chart's name, then the longer
one. A version must start the tag or follow a character other than a digit or dot, so `11.0.0`
doesn't count for `1.0.0`. Real repositories use `argo-cd-` (chart-releaser's default),
`external-dns-helm-chart-` next to the app's `v`, `cluster-autoscaler-chart-` next to the app's
`cluster-autoscaler-`, `helm-chart-` (external-secrets) and a plain `v` (keda in kedacore/charts,
cert-manager, whose chart shares the app's tags). Without a match, a subdirectory link or a GitHub
Pages repository gets chart-releaser's `<name>-`, and any other repository no prefix.

When a range endpoint is missing, the error says how many tags are versions after the prefix and
names up to 3 tags that hold the version, such as "0 of 133 tags of kubernetes-sigs/external-dns
are versions after the tag prefix "external-dns-"; tags that hold 1.23.0:
external-dns-helm-chart-1.23.0". It ends by pointing to a registry entry with
`version.tag_prefix`, tried with `relgap registry test <file.yaml> <range>`. `tools.<name>` takes
only `repo`, and a chart never takes another tool's entry.

`chart:<name>` without a repository, which pin discovery writes for `Chart.yaml` dependencies,
searches Artifact Hub. It resolves when one repository has a chart of that name, or when exactly
one of them is marked official (the project publishes it: argo-cd is argo's). Otherwise it fails
with the `chart:<repo>/<name>` candidates. On 2026-11-16, argo-cd was in 11 repositories,
external-dns in 9 and kube-state-metrics in 18.

`chart:<url>/<name>` names a chart by its Helm repository URL (`https://`, `http://` or `oci://`);
the chart is the part after the last `/`. It resolves through the Artifact Hub repository at that
URL that has the chart, the lookup pin discovery's `registry_url` uses, and never searches by name
([ADR-0016](../adr/0016-tool-identity-and-chart-registry-urls.md)). When Artifact Hub has no such
repository, it fails with "registryUrl <url> is not an Artifact Hub repository with a chart named
<name>".

Caches key on a tool's full name, never on the resolved spec's `name`: a chart and its
application can both resolve to `aws-for-fluent-bit` in different repositories.

Responses stay fresh for 24h (`cache.ttl_override` changes it). `--offline` fails a lookup that
isn't in the cache. `relgap drift` resolves from the registries alone, since it reads only version
rules and sends no request without `--latest`.

## `relgap registry update`

Lists `registry/` on the `main` branch of sassdavid/relgap through the contents API and downloads
each `.yaml` file there, with the HTTP cache's ETags. Each file is linted. One with problems, or
with a `min_relgap` newer than the binary, is skipped (development builds accept every
`min_relgap`). The files that differ from the embedded entries go to `<cache dir>/registry/`,
replacing the previous run's. Resolution loads them in place of the embedded entry of the same
name and lints them again, so a file edited by hand that fails is skipped with a warning.
`resolve` shows `relgap registry  updated` or `embedded` (`relgap_source` in JSON).
`relgap cache clear` deletes the directory.

## `--guess`

`resolve`, `digest <tool>` and `registry test` take `--guess`. For a plain name that no layer
knows, it searches GitHub (`<name> in:name`, 30 results by stars) and keeps repositories named
exactly `<name>`, ignoring case. The most-starred one wins and the others are listed as
`alternatives`. The result has `match.layer: github search` and `confidence: low`, and stderr
gets a warning that says to set `tools.<name>.repo`. Prefixed names, `outdated`, `drift` and the
MCP server never guess.

Entries also take `bin` (executable names for `outdated --binaries`), and sources take `content`,
`strip`, `anchor` and `json` (schema `schemas/registry-v1.json`, details in
[source-adapters.md](source-adapters.md)). `relgap registry test <tool|file.yaml> <range>` digests
the range once per source and once merged, and prints the versions, entry counts and documents of
each.

## Acceptance criteria
- [x] `relgap resolve tf`, `terraform`, `TERRAFORM_VERSION` and `aqua:hashicorp/terraform` all print the same ToolSpec, and the output shows which layer supplied each field.
- [x] Works with mise absent (embedded snapshot) and present (live `mise registry --json`), with the same results for the 30-tool corpus.
- [x] `tfprovider:hashicorp/aws` resolves to `hashicorp/terraform-provider-aws` with `CHANGELOG.md` as the source
  (`TestSpec_tool_resolution_3`, without a lookup).
- [x] `registry lint` rejects unknown keys and bad regexes with file:line errors.
- [x] Snapshot staleness check fails CI when the snapshot is over 30 days old (`registry.yml`,
  `TestSnapshotMeta_CheckAge`).
- [x] A chart's tag prefix comes from its repository's tags: `argo-cd-`, `cluster-autoscaler-chart-`,
  `external-dns-helm-chart-`, `metrics-server-helm-chart-`, `helm-chart-` (external-secrets) and
  `v` (cert-manager, keda) on real tag lists (`TestSpec_tool_resolution_6`, fixtures in
  `testdata/charttags/`).
- [x] `chart:<url>/<name>` resolves through the Artifact Hub repository at the URL and fails with
  the URL in the message when there is none, never searching by name; a chart pin and a
  `github:` pin whose specs share a name each compare against their own repository.
  (`TestSpec_tool_resolution_7`, `TestOutdatedSameNameDifferentTools`)
