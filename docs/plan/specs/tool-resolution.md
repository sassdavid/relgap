# Spec: tool resolution and the override registry

Maps a name ("terraform", "tf", "TERRAFORM_VERSION", "hashicorp/aws", "argo-cd") to a `ToolSpec`:
repo, version scheme, ordered changelog sources, EOL product and OSV packages.

## Resolution order (first hit wins, fields merge downward)
1. **Explicit syntax:** `github:owner/repo`, `aqua:owner/repo`, `tfprovider:ns/name` (→ registry.terraform.io → source repo), `chart:repo/name` (→ Artifact Hub → source repo), `npm:`/`pypi:` (→ package metadata repo URL).
2. **User config** `tools.<name>` overrides ([config.md](config.md)).
3. **relgap override registry:** `registry/<tool>.yaml`, embedded in the binary and refreshable from the repo (`relgap registry update`, ETag-cached).
4. **mise registry:** `mise registry --json` if mise is installed (1,074 entries). Otherwise an embedded snapshot of `registry/*.toml` (MIT, attributed). The first `aqua:`, `github:` or `ubi:` backend gives `owner/repo`; `aliases` give names.
5. **aqua registry:** an embedded index of `pkgs/**/registry.yaml` (about 2,353 entries) supplies `repo_owner/repo_name`, `version_prefix`, `version_filter`, `version_source`.
6. **endoflife.date identifiers:** `pkg:github/owner/repo` → EOL product.
7. **Heuristic:** search GitHub for an exact repo-name match, but only with `--guess`, and always reported as low-confidence.

The snapshots are regenerated by a `mise run registry:snapshot` task and committed. A CI job checks they're under 30 days old.

## Override registry entry (`registry/<tool>.yaml`)

```yaml
# registry/kubectl.yaml
name: kubectl
aliases: [kubernetes, k8s, KUBECTL_VERSION]
repo: kubernetes/kubernetes
version:
  tag_prefix: "v"
  exclude: "-(alpha|beta|rc)\\."     # regex on the tag
  universe: tags                     # tags | releases (what defines "versions in range")
sources:                             # tried and merged in order
  - kind: changelog-file
    path_template: "CHANGELOG/CHANGELOG-{major}.{minor}.md"
    ref: master
    heading: "^v{version}$"           # H1 per version
    ignore_sections: ["Dependencies"] # k8s "Dependencies › Removed" ≠ feature removals
  - kind: upgrade-notes
    from_heading: "Urgent Upgrade Notes"
eol: { product: kubernetes, cycle: "{major}.{minor}" }
osv:
  - { ecosystem: Go, name: k8s.io/kubernetes }
breaking_markers: ["ACTION REQUIRED"]
```

Schema: `schemas/registry-v1.json`. `relgap registry lint` validates an entry, and `relgap registry test kubectl 1.36.0..1.37.2` runs it live and prints which sources produced what.

(from the domain research): terraform, opentofu, terragrunt, kubectl, helm, argocd, awscli, claude-code,
mise, node, python, go, temurin/java, gh, k9s, uv, ruff, plus the Terraform providers `hashicorp/aws` and

`tfprovider:<namespace>/<name>` resolves to the curated entry whose repo is
`<namespace>/terraform-provider-<name>`. Other providers still need the Terraform registry lookup.
1password-cli has no public repository and stays unresolved; atlascli's notes are one mongodb.com
page for all versions, which web-doc doesn't split yet.

Entries also take `bin` (executable names for `outdated --binaries`), and sources take `content`,
`strip`, `anchor` and `json` (schema `schemas/registry-v1.json`, details in
[source-adapters.md](source-adapters.md)). `relgap registry test <tool|file.yaml> <range>` digests
the range once per source and once merged, and prints the versions, entry counts and documents of
each.

## Acceptance criteria
- [ ] `relgap resolve tf`, `terraform`, `TERRAFORM_VERSION` and `aqua:hashicorp/terraform` all print the same ToolSpec, and the output shows which layer supplied each field.
- [ ] Works with mise absent (embedded snapshot) and present (live `mise registry --json`), with the same results for the 30-tool corpus.
- [ ] `tfprovider:hashicorp/aws` resolves to `hashicorp/terraform-provider-aws` with `CHANGELOG.md` as the source.
- [ ] `registry lint` rejects unknown keys and bad regexes with file:line errors.
- [ ] Snapshot staleness check fails CI when the snapshot is over 30 days old.
