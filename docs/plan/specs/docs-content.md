# Spec: docs site content (relgap)

What the site at `https://relgap.sasskovacs.dev` contains, where each page gets its facts, and
which statements in today's docs and help texts are wrong. The build and generators are in
[docs-site](docs-site.md), the design in [docs-design](docs-design.md).

The audit behind this spec ran on 2026-11-17 against `main` after v0.4.0. It read every command
in `internal/cli`, the Config struct, the schemas and the user docs, built the binary to run
`--help`, `version` and `config show`, and regenerated `docs/cli` to confirm the checked-in copy
was current. It made no network calls. Code wins wherever code and docs disagree. Each milestone
that writes pages reruns the parts of the audit it touches, because file and line references go
stale.

## Structure

Diataxis: a tutorial to start, how-to guides, concepts (explanation) and reference. Kind: Gen =
generated by a Go program, Hand = written by hand, Port = moved from an existing doc and
rewritten to the writing rules.

## Gaps: features with no user doc

Each is covered by the page named in the structure above.

- `--summarize` and the `llm` config: providers, key handling, timeouts, what is sent.
- `registry update` and `registry test` (README mentions only `registry lint`).
- Input syntaxes `tfprovider:`, `chart:`, `npm:`, `pypi:`, the remote lookups behind them, and
  `--guess`.
- `drift --from-tfcensus`, `pins --renovate-report`, `outdated --binaries`.
- Cache TTL rules, `cache.ttl_override`, `prune`, `--offline`, `--refresh`, `--no-cache`.
- Config keys `ignore`, `aliases`, `tools`, `scan.detectors.*`, `scan.extra_files`.
- Exit codes 2, 4 and 130 (README mentions only 3).
- Token lookup order and unauthenticated rate limits.
- relgap-action (published on the Marketplace, not mentioned in README or `docs/ci`).
- The report JSON schemas (README links only the config and registry schemas).
- The MCP prompt `upgrade_review` and entry IDs.
- The network hosts and subprocesses relgap uses.
- Classification confidence levels.
- The supported tools list and what "supported" means for the rest.

## Gaps: generated `docs/cli`

Fixed by the generator in [docs-site](docs-site.md#cli-reference):

- cobra file names, `##` as the top heading, no frontmatter.
- The 13 global flags repeated on every page; `--format` listing sarif and github on every page
  although only `outdated` and `drift` accept them.
- `[=true|false]` on every bool flag.
- Raw `<tool>`, `<from>`, `<to>`, `<ref>`, `<command>`, `<path>`, `<roots...>`, `<name>` and
  `<details>` outside code. GitHub strips them today, and `<details>` opens a collapsible block.
- Indented tables in help text (resolve layers, MCP tools, notify targets, config layers) that
  Markdown folds into one paragraph.
- cobra's completion text with `####` headings; the overlong line in the digest `Long` text; the
  digest synopsis with `[flags]` after the last alternative; a blank line inside the `outdated`
  examples.

## Generated by scripts/gensite

`mise run docs` runs `scripts/gensite`, which writes these files and fails when one changed. No
generator parses Go source: each table reads an exported list, and a test ties that list to the
code.

| File | Read from | Test |
|---|---|---|
| `docs/reference/tools.md` | `registry.Linter.LoadFS` over the embedded entries | the registry lint |
| `docs/reference/snapshots.md` | `registry.MiseSnapshot`, `registry.AquaSnapshot` | |
| `docs/reference/registry-schema.md` | `schemas/registry-v1.json` | `TestSourceKinds` |
| `docs/reference/sarif-rules.md` | `render.SARIFRule`, `OutdatedRules`, `DriftRules` | the SARIF goldens |
| `docs/parts/detectors.md` | `scan.DetectorDocs` | `TestDetectorDocs` (each example path is read by its detector only) |
| `docs/parts/source-kinds.md`, `placeholders.md`, `web-hosts.md` | `source.Kinds`, `registry.Placeholders` with `source.ExpandPrev`, `registry.WebHosts` | `TestSourceKinds`, `TestPlaceholders` |
| `docs/parts/confidence.md` | `classify.Signals` | `TestSignals` (every rule's confidence has a row) |
| `docs/parts/network-hosts.md` | host constants of `httpx`, `enrich`, `remote`, `registry` and `summarize` | `TestNetworkHosts` (every host in the cassettes is listed) |
| `docs/parts/relgap-action.md` | `scripts/gensite/relgap-action.yml`, the action's `action.yml` at the commit `docs/ci/relgap-action.yml` pins | `TestActionPart`; `mise run docs:action` refreshes the copy |
| `docs/.vitepress/theme/data/sent-to-model.json` | `summarize.SentToModel` | `TestSentToModel` (the fields match the user message `Summarize` builds) |
| `docs/.vitepress/theme/data/home-strata.json` | `testdata/golden/digest/kubectl.json` | `TestBuildStrata` |

`docs/parts/` holds fragments that pages include with `<!--@include: -->`. It is in `srcExclude`,
so VitePress builds no page from it. The concept pages of M25 include the detector, source,
confidence and action fragments.

gensite also checks transcripts: every golden file a page includes with `<<<` must follow the
`relgap` command that a test script runs before comparing its output with that file.

## Never on the site

- Tokens of any kind. Examples use `${{ github.token }}` or a `GH_TOKEN` placeholder. The repo is
  clean today (the only match is the test assertion in `testdata/script/cache.txtar`).
- `docs/dogfood.md` as it is (USD costs, token counts, branch and commit SHAs, local setup). Only
  its setup commands move into the MCP guide.
- Internal material: `docs/plan/`, `docs/engineering/`, milestone names, CLAUDE.md,
  `.claude/rules/`, cassettes. The changelog page is the one exception for milestone names: it
  includes `CHANGELOG.md` as release-please writes it, and older commit subjects name milestones
  (decided in M24).
- Dev-only variables and tasks: `RELGAP_LIVE_OUT`, `RELGAP_BEDROCK_MODEL`, `test:live*`.
- Local paths and machine details (`/Users/...`, `~/src/github/...`, AWS profile names).
- Homebrew and Scoop install steps until the package channels publish.

## Acceptance criteria

1. Every page in the structure exists with a `description`, or the milestone that owns it lists
   it as moved to a later one.
2. Every item under "features with no user doc" is covered by a page.
3. Every row under "wrong or stale statements" is fixed in code or docs, with the commit named in
   the milestone evidence.
4. The never-on-the-site checks (token grep, link rule, local-path grep) pass on the built site.
5. README keeps a short introduction, the install command and links to the site, and no longer
   carries guide content.
